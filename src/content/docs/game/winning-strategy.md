## 1. 概要

二人零和有限確定ゲームで、勝敗や必勝戦略を決めるための考え方をまとめる.

- 後退解析（3 章）: 終了局面から逆向きに、各局面の勝ち負けを決めていく. ループがあって引き分けがあるゲームにも使える.
- 手数の偶奇（4 章）: 終了までの手数の偶奇がプレイによらず決まるなら、偶奇だけで勝敗が決まる.
- まねっこ戦略（5 章）: 盤面を対称に保つように相手の手をまねる. 勝ち方が具体的に分かる.
- ペアリング戦略（6 章）: 手を 2 つずつ組にし、相手が組の片方を使ったらもう片方を使う. グラフ上のゲームでは最大マッチングを組に使う.
- 戦略泥棒（7 章）: 「後手に必勝戦略があるなら、先手がその戦略を盗める」という背理法で先手必勝を示す. 勝ち方は分からないが、勝敗だけは分かる.
- 得点を競うゲーム（8 章）: 「手番の人の得点 − 相手の得点」を DP で求める.

特に断らない限り、ゲームは次の条件を満たすとする.

- 2 人が交互に手を打ち、どの局面でも有限回の手で終わる.
- 引き分けはなく、手を打てなくなった人が負ける（正規形）.

このとき、各局面は「手番の人が勝つ局面（N 局面）」と「手番の人が負ける局面（P 局面）」のどちらかに分かれる.

## 2. 前提知識

- [Nim](../../game/nim/)（Grundy 数と、ゲームの和の Grundy 数が XOR になること）

## 3. 後退解析

### 3.1. P 局面と N 局面

<a id="claim-3-1"></a>

:::note[主張 3.1]
局面 $P$ が P 局面であることと、$P$ から 1 手で行ける局面がすべて N 局面であることは同値である（行ける局面がない $P$ も P 局面）.
:::

<details><summary>証明</summary>

$P$ から 1 手で P 局面 $Q$ に行けるなら、手番の人は $Q$ に移せば勝つので、$P$ は N 局面である.
$P$ から 1 手で行ける局面がすべて N 局面なら、手番の人がどう打っても相手が勝つので、$P$ は P 局面である.

</details>

局面を頂点、手を辺とした有向グラフはループのない DAG になるので、主張 3.1 を使って終了局面から順に勝ち負けを決められる（メモ化再帰や、局面が小さくなる順の DP）.
計算量は局面数と手の数の和である.

:::tip
局面数が多すぎて全部は調べられないときも、小さい盤面だけ後退解析で勝ち負けを求めると、P 局面の規則（周期、偶奇、特定の形）が見えることが多い. 規則を予想したら、主張 3.1 の 2 条件（P 局面からは N 局面にしか行けない、N 局面からは P 局面に行ける）を確かめて証明する.
:::

### 3.2. ループがあるゲーム

手を繰り返して同じ局面に戻れるゲームでは、局面のグラフにループがあり、ゲームが終わらないことがある.
両者が最善を尽くしてもゲームが終わらない局面を引き分けとし、各局面を勝ち・負け・引き分けに分ける.
次の手順で、グラフの頂点数と辺数の和の時間で求められる.

1. 行ける局面がない局面を負けと決め、キューに入れる.
2. 各局面 $v$ に、勝ちと決まっていない行き先の数 $d_v$（はじめは $v$ から出る辺の数）を持たせる.
3. キューから局面 $u$ を取り出し、$u$ へ 1 手で来られる、まだ決まっていない局面 $v$ について次を行う.
   - $u$ が負けなら、$v$ を勝ちと決めてキューに入れる.
   - $u$ が勝ちなら、$d_v$ を 1 減らす. $d_v = 0$ になったら、$v$ を負けと決めてキューに入れる.
4. キューが空になったときに決まっていない局面を引き分けとする.

<a id="claim-3-2"></a>

:::note[主張 3.2]
3.2 節の手順で勝ち・負けと決めた局面は、手番の人が勝つ・負ける局面である. 決まらなかった局面では、両者が最善を尽くすとゲームが終わらない.
:::

<details><summary>証明</summary>

勝ち・負けと決めた局面については、決めた順番に関する帰納法で、主張 3.1 と同じ理由で正しい.

決まらなかった局面 $v$ を考える. $v$ から負けの局面に行ける辺があれば $v$ は勝ちと決まるので、$v$ から行ける局面は勝ちか、決まらなかった局面である. 行き先がすべて勝ちなら $d_v = 0$ となり $v$ は負けと決まるので、決まらなかった局面へ行く辺が少なくとも 1 本ある.
よって $v$ で手番の人は、決まらなかった局面へ移り続けることで負けを避けられる. 勝ちの局面へ移ると相手が勝つので、相手も決まらなかった局面へ移り続ける. 両者とも相手に勝つことを強制できないので、ゲームは終わらない.

</details>

実装は 10.1 節にある.

## 4. 手数の偶奇

### 4.1. 主張

<a id="claim-4-1"></a>

:::note[主張 4.1]
どう打っても、ゲームが終わるまでの手数が同じ値 $T$ になるとする. このとき、$T$ が奇数なら先手必勝、偶数なら後手必勝である.
:::

最後の手を打った人が勝つので、主張 4.1 はそのまま成り立つ. 手数を直接数えにくいときは、1 手ごとにちょうど 1 だけ増える（減る）量 $\Phi$ を探す. 初期局面と終了局面の $\Phi$ の差が手数になる.

### 4.2. 例: チョコレートを割る

> $h \times w$ の板チョコがある. 2 人が交互に、かけらを 1 つ選び、溝に沿って 2 つのかけらに割る. 割れなくなった（すべてのかけらが $1 \times 1$ になった）人が負け.

$\Phi$ をかけらの数とすると、1 回割るごとに $\Phi$ はちょうど 1 増える.
はじめ $\Phi = 1$、終了時 $\Phi = hw$ なので、手数は割り方によらず $hw - 1$ である. よって $hw$ が偶数なら先手必勝である.

### 4.3. 終了局面の形から偶奇を決める

終了局面が 1 つに決まらなくても、終了局面の $\Phi$ の偶奇が初期局面から決まれば、主張 4.1 と同じく手数の偶奇から勝敗が決まる.
終了局面（手を打てない局面）の形を書き出し、ゲームの間ずっと変わらない量（端の文字、総和の偶奇など）と結びつけるとよい.
[ABC048 D](../../problems/abc048-d/) がこの形の問題である.

## 5. まねっこ戦略

### 5.1. 応手で戻れる局面の集合

まねっこ戦略は次の主張を具体的な盤面に当てはめたものである.

<a id="claim-5-1"></a>

:::note[主張 5.1]
局面の集合 $S$ が次の条件を満たすとする.

- 任意の $P \in S$ と、$P$ から 1 手で行ける任意の局面 $Q$ について、$Q$ から 1 手で行ける局面 $P' \in S$ がある.

このとき、$S$ に属する局面はすべて P 局面である.
:::

<details><summary>証明</summary>

手番の人を A、相手を B とする. 局面 $P \in S$ で A が手を打って局面 $Q$ になったら、B は条件の手で $P' \in S$ に戻す.
B は $S$ の局面に戻す手を常に打てるので、A が手を打てる限り B も手を打てる.
ゲームは有限回で終わるので、いずれ A が $S$ の局面で手を打てなくなり、A が負ける.

</details>

主張 5.1 の B の戦略を**応手戦略**と呼ぶことにする. 応手戦略は具体的な手順なので、インタラクティブ問題でもそのまま実装できる.

### 5.2. 対称な盤面

$S$ の典型は「同じ盤面 $G$ を 2 つ並べた局面」である.
$G$ のコピーを $G_1, G_2$ とし、局面 $G_1 + G_2$ を考える.
相手が $G_1$ で手を打ったら $G_2$ で同じ手を打ち、$G_2$ で手を打ったら $G_1$ で同じ手を打つ.
応手の後は再び 2 つの盤面が一致するので、主張 5.1 の条件を満たす.
Grundy 数で言えば、$g(G_1 + G_2) = g(G) \oplus g(G) = 0$ である.

より一般に、盤面の対称変換 $\sigma$（例: 列の左右反転、盤の点対称移動）があり、

1. 対称な局面で打てる任意の手 $m$ について、$m$ を打った後も $\sigma(m)$ が打てる,
2. $m$ と $\sigma(m)$ を打った後の局面は再び対称である,

の 2 つが成り立てば、対称な局面は P 局面である.
条件 1 が崩れるのは、手 $m$ と手 $\sigma(m)$ が同じ場所を使うとき（例: 列の中央をまたいで取る手）である.
対称軸の上にある部分を最初に取り除いておくと、条件 1 が成り立つことが多い.

:::tip
まねっこ戦略を使うときは、次のどちらかを狙う.

- 先手: 最初の 1 手で盤面を対称にし、以降はまねる（先手必勝）.
- 後手: 相手の 1 手目の後、自分の 1 手目で盤面を対称にし、以降はまねる（後手必勝）.
:::

### 5.3. 例: 円形に並んだコイン

> $n$ 枚のコインが円形に並んでいる. 2 人が交互に、1 枚のコインか隣り合う 2 枚のコインを取る. 取れなくなった人が負け.

$n \ge 3$ なら後手必勝である.
先手が 1 枚か 2 枚取ると、残ったコインは長さ $n - 1$ か $n - 2$ の一列になる.
後手は一列の中央から、一列の長さと偶奇が一致するように 1 枚か 2 枚を取り、同じ長さの列を 2 本作る.
以降は 2 本の列の間で相手の手をまねる.

一列に並んでいる場合（$n$ 枚が一列）は、先手が中央から $n$ と偶奇の一致する枚数を取れば先手必勝になる.
[ABC278 G](../../problems/abc278-g/) は取る枚数を $L$ 以上 $R$ 以下にした問題である.

### 5.4. 不変量を保つ応手

$S$ は対称な局面でなくてもよい. 「ある量が特定の値になる局面」を $S$ にし、相手の手で崩れた量を自分の手で元に戻す応手もよく使う.

> $n$ 個の石の山があり、2 人が交互に 1 個以上 $K$ 個以下の石を取る. 取れなくなった人が負け.

$S = \lbrace n : n \equiv 0 \pmod{K + 1} \rbrace$ とする. 相手が $x$ 個取ったら自分は $K + 1 - x$ 個取ると、2 手で合計 $K + 1$ 個減るので $S$ に戻る. よって $n \equiv 0 \pmod{K + 1}$ なら後手必勝である.
Nim の「XOR が $0$ の局面」も、主張 5.1 の $S$ の例である.

## 6. ペアリング戦略

### 6.1. 考え方

まねっこ戦略は、盤面の場所を $x$ と $\sigma(x)$ の組に分け、相手が組の片方を使ったら自分がもう片方を使う戦略とみなせる.
組が対称な位置になくても、「相手が組の片方を使ったら、組のもう片方が必ず使える」ように組を作れれば、同じように応手戦略になる.
グラフ上のゲームでは、組として最大マッチングを使うことが多い.

### 6.2. 例: グラフ上でコマを動かす

> 無向グラフ $G$ の頂点 $v$ にコマがあり、$v$ は訪問済みとする. 2 人が交互に、コマを隣接する未訪問の頂点へ動かし、動かした先を訪問済みにする. 動かせなくなった人が負け.

<a id="claim-6-1"></a>

:::note[主張 6.1]
先手必勝であることと、$G$ のすべての最大マッチングが $v$ を含む（$v$ を端点とする辺を含む）ことは同値である.
:::

<details><summary>証明</summary>

コマが通った頂点を順に $x_0 = v, x_1, x_2, \dots$ とする.

（すべての最大マッチングが $v$ を含むとき）最大マッチング $M$ を 1 つ取る. 先手は、コマのある頂点の $M$ での相手へコマを動かす.
後手がコマを $x_{2k}$ に動かした時点で、$x_0 x_1, x_2 x_3, \dots, x_{2k-2} x_{2k-1}$ は $M$ の辺で、$x_{2k}$ は未訪問だった頂点である.
$x_{2k}$ が $M$ に含まれないとすると、パス $x_0 x_1 \cdots x_{2k}$ に沿って $M$ の辺と $M$ でない辺を入れ替えれば、大きさが同じで $v$ を含まない最大マッチングができ、仮定に反する.
よって $x_{2k}$ には $M$ での相手 $y$ がいる. 訪問済みの頂点 $x_0, \dots, x_{2k-1}$ は $M$ で互いに組になっているので、$y$ は未訪問であり、先手はコマを $y$ に動かせる.
先手は常に動かせるので、ゲームが有限回で終わることから先手が勝つ.

（$v$ を含まない最大マッチング $M$ があるとき）後手は、コマのある頂点の $M$ での相手へコマを動かす.
先手がコマを $x_{2k+1}$ に動かした時点で、$x_1 x_2, \dots, x_{2k-1} x_{2k}$ は $M$ の辺である.
$x_{2k+1}$ が $M$ に含まれないとすると、パス $x_0 x_1 \cdots x_{2k+1}$ は両端が $M$ に含まれない交互パス（増加パス）なので、$M$ の辺と $M$ でない辺を入れ替えると $M$ より大きいマッチングができ、$M$ が最大であることに反する.
よって $x_{2k+1}$ の $M$ での相手 $y$ がいて、先ほどと同じ理由で $y$ は未訪問なので、後手はコマを $y$ に動かせる. よって後手が勝つ.

</details>

すべての最大マッチングが $v$ を含むかどうかは、「$G$ の最大マッチングの大きさ」と「$G$ から $v$ を除いたグラフの最大マッチングの大きさ」が異なるかどうかで判定できる.

## 7. 戦略泥棒

### 7.1. 主張

<a id="claim-7-1"></a>

:::note[主張 7.1]
初期局面を $P_0$ とする. $P_0$ からの 1 手 $m_0$ で局面 $P_1$ になるとし、次の条件を満たすとする.

- $P_1$ から 1 手 $r$ で行ける任意の局面 $P_2$ について、$P_0$ から 1 手で $P_2$ に行ける.

このとき、$P_0$ は N 局面（先手必勝）である.
:::

<details><summary>証明</summary>

$P_1$ が P 局面なら、先手は $m_0$ を打てば勝つ.

$P_1$ が N 局面なら、$P_1$ から 1 手で行ける P 局面 $P_2$ がある.
条件より $P_0$ から 1 手で $P_2$ に行けるので、先手は $P_2$ に行く手を打てば勝つ.

どちらの場合も $P_0$ は N 局面である.

</details>

$m_0$ は「ほぼパス」の手である. 後手に必勝の応手 $r$ があるなら、先手は $m_0$ を打たずに最初から $r$ の結果の局面へ行けばよい. 後手の勝ちパターンを先手が盗むので、戦略泥棒（strategy-stealing argument）と呼ばれる.

戦略泥棒で分かるのは「先手必勝であること」だけで、先手がどの手を打てば勝てるかは分からない.
競技プログラミングでは、出力が先手・後手の判定だけで、小さいケースを全探索すると先手必勝ばかりになるときに疑うとよい.

:::note
引き分けがあるゲーム（三目並べなど）では、同じ議論で「後手必勝ではない」ことが言える. ただし、余分に置いた石が不利にならないことを別に確かめる必要がある.
:::

### 7.2. 例: チョコレート（Chomp）

> $h \times w$ のチョコレートがあり、左下の 1 マス $(1, 1)$ だけに毒がある. 2 人が交互に、残っているマス $(i, j)$ を 1 つ選び、$i' \ge i$ かつ $j' \ge j$ を満たすマス $(i', j')$ をすべて食べる. 毒のマスを食べた人が負け.

毒のマスだけが残った局面で手番の人は負けるので、毒のマスを除いた正規形のゲームと考えてよい. $hw \ge 2$ なら先手必勝である.

$m_0$ を「右上の角 $(h, w)$ だけを食べる手」とする.
$m_0$ の後に後手がマス $(i, j)$ を選んだとすると、$(h, w)$ は $i \le h$ かつ $j \le w$ を満たすので、$(i, j)$ を選ぶ手で食べられる範囲に $(h, w)$ が含まれる.
よって、$m_0$ の後に $(i, j)$ を選んだ結果は、初期局面で $(i, j)$ を選んだ結果と同じであり、主張 7.1 の条件を満たす.

### 7.3. 例: 約数を消すゲーム

> $1, 2, \dots, N$ が書かれている. 2 人が交互に、残っている数 $x$ を 1 つ選び、$x$ の約数のうち残っているものをすべて消す. 消せなくなった人が負け.

どの $N$ でも先手必勝である.
$m_0$ を「$1$ を選ぶ手」とすると、$m_0$ で消えるのは $1$ だけである.
$m_0$ の後に後手が $x$ を選んだ結果は、初期局面で $x$ を選んだ結果と同じ（$x$ の約数がすべて消え、$1$ も消えている）ので、主張 7.1 の条件を満たす.

## 8. 得点を競うゲーム

### 8.1. 得点差の DP

各手で手番の人が得点を得て、終了時の得点の大小を競うゲームを考える（正規形ではない）.
両者が「自分の得点 − 相手の得点」を最大化するとき、局面 $P$ から終了までに手番の人が得る得点と相手が得る得点の差の最適値 $f(P)$ は、手 $m$ で得る得点を $c(m)$、$m$ を打った後の局面を $P_m$ として

$$
f(P) = \max_{m} \bigl( c(m) - f(P_m) \bigr)
$$

で求められる（終了局面では $f(P) = 0$）. $P_m$ では相手が手番になるので、$f(P_m)$ は相手から見た得点差であり、符号を反転して足す.
得点の合計が打ち方によらず一定なら、「自分の得点を最大化する」ことと「得点差を最大化する」ことは同じなので、自分の得点を最大化するゲームもこの DP で解ける.

### 8.2. 例: 同じ価値の品物を交互に取る

> 価値 $a_1 \ge a_2 \ge \dots \ge a_m$ の品物がある. 2 人が交互に品物を 1 つ取り、取った品物の価値の合計を自分の得点とする.

<a id="claim-8-1"></a>

:::note[主張 8.1]
両者とも残っている品物のうち価値が最大のものを取るのが最適であり、先手の得点 − 後手の得点は $A = a_1 - a_2 + a_3 - \cdots + (-1)^{m+1} a_m$ である.
:::

<details><summary>証明</summary>

$m$ に関する帰納法で示す. 品物 $i$ を取ったときの得点差は、帰納法の仮定より、品物 $i$ を除いた $m - 1$ 個の品物の交代和を $A_i$ として $a_i - A_i$ である.
$A_i$ では、$k < i$ の $a_k$ の符号は $A$ と同じで、$k > i$ の $a_k$ の符号は $A$ と逆になる. よって

$$
A - (a_i - A_i) = 2 \sum_{k < i} (-1)^{k+1} a_k + \bigl( (-1)^{i+1} - 1 \bigr) a_i
$$

である. $i$ が奇数なら右辺は $2 \bigl( (a_1 - a_2) + \cdots + (a_{i-2} - a_{i-1}) \bigr) \ge 0$、$i$ が偶数なら $2 \bigl( (a_1 - a_2) + \cdots + (a_{i-1} - a_i) \bigr) \ge 0$ である.
よって $i = 1$（得点差 $A$）が最適である.

</details>

品物 $i$ の価値が先手にとって $a_i$、後手にとって $b_i$ と異なるときは、先手が取る品物の集合を $X$ とすると

$$
(\text{先手の得点}) - (\text{後手の得点}) = \sum_{i \in X} a_i - \sum_{i \notin X} b_i = \sum_{i \in X} (a_i + b_i) - \sum_{i} b_i
$$

となる. 後手の得点 − 先手の得点も同じく $\sum_{i \notin X} (a_i + b_i) - \sum_i a_i$ と書けるので、両者とも価値 $a_i + b_i$ の品物を取り合うゲームになり、主張 8.1 より $a_i + b_i$ の大きい順に取るのが最適である.

## 10. コード

### 10.1. 後退解析（3 章）

- `solve_game(n, edges)`: 頂点 $0, \dots, n-1$ と有向辺 `edges`（`{v, u}` は頂点 $v$ から $u$ へ 1 手で移れることを表す）のゲームを解く. 戻り値 `res[v]` は、頂点 $v$ で手番の人が勝つなら $1$、負けるなら $-1$、引き分けなら $0$. $O(n + |E|)$.
- 同じ辺が複数あってもよい.

```cpp title="solve_game.cpp"
vector<int> solve_game(int n, const vector<pair<int, int>> &edges) {
    vector<vector<int>> rev(n);
    vector<int> deg(n, 0);  // 勝ちと決まっていない行き先の数
    for (auto [v, u] : edges) {
        rev[u].push_back(v);
        deg[v]++;
    }
    vector<int> res(n, 0);
    queue<int> q;
    for (int v = 0; v < n; v++) {
        if (deg[v] == 0) {
            res[v] = -1;
            q.push(v);
        }
    }
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int v : rev[u]) {
            if (res[v] != 0) continue;
            if (res[u] == -1) {
                res[v] = 1;  // 負けの局面へ移れる
                q.push(v);
            } else if (--deg[v] == 0) {
                res[v] = -1;  // どこへ移っても相手の勝ち
                q.push(v);
            }
        }
    }
    return res;
}
```
